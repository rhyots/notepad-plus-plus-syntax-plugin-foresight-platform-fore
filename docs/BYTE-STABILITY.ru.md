# Точные байты при переключении Git

[English](BYTE-STABILITY.md) | [Русский](BYTE-STABILITY.ru.md)


Проект сохраняет исходные байты, к которым привязаны нативные проверки. Это предотвращает расхождение Windows CRLF / Unix LF, ранее возникшее в упакованном JavaScript другого проекта.

- `.gitattributes` задаёт LF для поддерживаемых текстовых файлов, включая YAML workflow и PowerShell-скрипты. PowerShell 7 поддерживает LF.
- `src/`, `styles/`, `examples/`, `vendor/` и сохранённые нативные снимки/метрики используют `-text`: Git не должен преобразовывать переводы строк. `ForeWords.h` намеренно сохраняет CRLF генератора; уведомления SDK сохраняют исходные байты.
- `.editorconfig` фиксирует настройки редактора.
- `byte-lock.json` содержит SHA-256 исходников, палитр, примеров и сторонних файлов. `tools/check_bytes.py` отклоняет дрейф байтов и CRLF/BOM в скриптах автоматизации.
- Нативные результаты отдельно привязаны к DLL, палитрам, примерам и исходникам лексера. Обновлённый byte-lock не заменяет новый нативный прогон при изменении реализации или байтов палитры.

`python tools/checkout_audit.py` создаёт изолированный временный Git-репозиторий внутри игнорируемого `build/checkout-audit/`. Он действительно добавляет и коммитит публичные исходники, дважды клонирует их и выполняет checkout с `core.autocrlf=false` и `true` (во втором случае также с `core.eol=crlf`). Сравниваются хеши всех файлов, повторно генерируется словарь, проверяются результаты тестов и одинаковый SHA-256 двух исходных ZIP. Удалённый репозиторий не создаётся, в рабочий проект коммит не добавляется. Результаты: `qa/checkout-validation.json`.

Хеши ZIP в этом отчёте относятся к временному снимку аудита. Хеши окончательных архивов выпуска сохраняются отдельно в `dist/*.sha256`.

Матрица GitHub Actions повторяет проверки на Windows и Ubuntu с обоими режимами autocrlf. Успешный локальный аудит сам по себе не является успешным удалённым запуском GitHub Actions.

Упаковщик читает файлы через `read_bytes()`. Пути ZIP отсортированы, метки времени и Unix-атрибуты фиксированы, используется ZIP_STORED для независимости от версии библиотеки сжатия. Переводы строк при упаковке не меняются. После записи проверяется каждый файл, создаются манифесты SHA-256 и отдельный файл хеша архива. Это воспроизводимость упаковки одинаковых входных данных, а не обещание одинаковых DLL у разных компиляторов.

При намеренном изменении отредактируйте исходник, при необходимости обновите `ForeWords.h`, выполните `python tools/check_bytes.py --write`, пересоберите и повторите требуемые нативные тесты, затем проверки байтов и checkout. Не меняйте ожидаемый хеш только ради устранения ошибки. Каталоговый `id` вычисляйте по окончательному ZIP Plugins Admin: любое изменение содержимого делает предыдущий `id` неверным.

Официальные правила Git: [gitattributes](https://git-scm.com/docs/gitattributes).

## Требования

| Требование | Данные проекта |
|---|---|
| Записи по архитектурам | `catalog/plugin-x64.draft.json` и `catalog/plugin-x86.draft.json`; целевые файлы `src/pl.x64.json` и `src/pl.x86.json` |
| Уникальное имя папки совпадает с DLL | `ForeLexer` / `ForeLexer.dll` |
| DLL в корне ZIP | Отдельные `*-plugins-admin-x64.zip` и `*-plugins-admin-x86.zip` |
| Версия DLL совпадает с каталогом | Windows VERSIONINFO `1.1.0.0`, каталог `1.1.0` |
| Хеш всего пакета | `id` — SHA-256 окончательного ZIP, а не DLL; вычисляется после упаковки |
| Обязательные поля JSON | folder-name, display-name, version, id, repository, description, author, homepage |
| URL скачивания | Файл конкретного GitHub Release; настоящее скачивание проверяется до заявки |
| Совместимость | `[8.9.8.1,]`, минимальная проверенная версия редактора на каждой архитектуре |
| Исходники и лицензии | Полный исходный ZIP, MIT для собственного кода, сторонние условия сохранены |

Unicode-экспорты, машинная архитектура, точки входа ILexer5, версия и обе встроенные палитры проверяются по настоящей DLL. На **каждой архитектуре** в Notepad++ 8.9.8.1 прошли 381 нативное утверждение в 18 сценариях, 17 сценариев распознавания, 40 проверок тем и изолированная проверка установщика. Общие наборы ядра/распознавателя дали 53/104 утверждения. [Подробности](TESTING.ru.md).

## Установка, обновление и удаление

Официальная инструкция рекомендует portable Notepad++ с официальными Debug Notepad++ и Debug WinGUp и локальным тестовым каталогом. Изолированная среда использует официальные артефакты и коммит Notepad++ данного выпуска. Рабочая установка пользователя не меняется.

Тестовый Plugins Admin открыт; наблюдались вкладки Available/Updates/Installed. Последующие обращения к дереву доступности и снимкам завершались таймаутами. Поэтому полный цикл кликами в Plugins Admin **не объявляется пройденным**.

Штатный **WinGUp CLI**, установочный механизм Plugins Admin, проверяется с публичными HTTPS-адресами выпусков и SHA-256 каталога, затем настоящим перезапуском редактора и существующим нативным интеграционным тестом. Все шесть операций прошли: x64 — установка 1.0.0, обновление до 1.1.0 и удаление; x86 — первая установка 1.1.0, обновление/переустановка той же версии и удаление. Более раннего публичного выпуска x86 нет. После установки/обновления нативный тест подтвердил меню Fore, Конфигуратор стилей и About; после удаления DLL и пункт Fore исчезли. Пользовательский XML сохранил точные байты. [Полные результаты и хеши инструментов](../qa/plugins-admin-lifecycle.json).

Проверка содержимого пакета отдельно проверяет создание `ForeLexer.xml` при первом запуске, сохранение изменённого XML и регистрацию в Language → F → Fore и Конфигураторе стилей. Нативные результаты связаны с хешами DLL/палитр. Обычная установка в APPDATA этими portable-тестами не подтверждается. Одного `-settingsDir` недостаточно для изоляции плагинового профиля: [исходный код конфигурации](https://github.com/notepad-plus-plus/notepad-plus-plus/blob/dd40fe45598791e9aa38f3aeb200e10fb3d6338a/PowerEditor/src/Parameters.cpp#L1330).

Руководство описывает перенос `doc/` в `plugins/doc/ForeLexer/`; проверенный отладочный WinGUp оставил его в `plugins/ForeLexer/doc/`. Ссылки документации архивов ведут к зафиксированной версии репозитория и работают в обоих местах.

## Воспроизводимые проверки и последовательность подачи

1. Отдельно собрать и проверить x64/x86. Создать два окончательных каталоговых ZIP и записи JSON.
2. Пройти CI Windows x64/x86 и Linux с проверкой checkout LF/CRLF. [Workflow](https://github.com/rhyots/notepad-plus-plus-syntax-plugin-foresight-platform-fore/actions/workflows/build.yml).
3. Опубликовать неизменяемые архивы, скачать их обратно и сравнить SHA-256 всего ZIP с `id`. Если используется подпись, подписывать до упаковки/хеширования.
4. Выполнить неизменённый официальный валидатор и схему с настоящими публичными загрузками; завершить проверки установки/обновления/удаления WinGUp и сохранить способ/ограничения в отчётах.
5. Отправить только записи x64/x86. Принятие и распространение остаются решением сопровождающих каталога.

Исторические отчёты на теге v1.0.0 описывают прежнюю офлайн-проверку валидатором и извлечённый пакет. Они не заменяют проверок публичной загрузки или жизненного цикла новой версии. [Стабильность байтов](BYTE-STABILITY.ru.md) описывает настоящий Git checkout и отклонение дрейфа LF→CRLF.

Повторение зафиксированного локального аудита в Windows:

```powershell
python -m pip install --target build/catalog-deps -r requirements-catalog.txt
python tools/catalog_audit.py --refresh
```

`--refresh` скачивает зафиксированные источники, а не изменяемый master. Для обновления аудита правил в будущем нужно намеренно обновить коммиты и повторить проверки.

# Журнал подготовки выпуска по ub-mode

[English](UB-MODE-REVIEW.md) | [Русский](UB-MODE-REVIEW.ru.md)


Дата: 31.10.2026. Цель: проверить код, уменьшить обоснованную сложность и
подготовить чистый первый выпуск 1.0.0 без публикации.

Применён локально установленный навык [ub-mode](https://github.com/unclebob/ub-mode/blob/master/SKILL.md).
Прямая инструкция пользователя «пока ничего не заливай» исключает push и
любые отправки во внешние репозитории. Локальные коммиты при наличии/создании
рабочего репозитория допустимы; внешняя публикация не выполняется.

## Журнал действий и причин

1. Прочитан SKILL.md и проверены инструкции рабочей папки — определить правила
   и границы работы до изменений.
2. Проверены публичные файлы, существующие отчёты и `.gitattributes` — сохранить
   проверенную исходную точку и привязку результатов к байтам.
3. Проверены доступность и официальные README Crapper, Dryer, Mutator — выяснить
   реальную область поддержки. Эти инструменты поддерживают Python, но не C++.
   Их результаты не будут выдаваться за измерения C++.
4. Найдены дублированное имя ZIP в README и крупная функция распознавания —
   наметить конкретные изменения вместо механического переписывания всего проекта.
5. Инструменты анализа загружаются в игнорируемый `build/ub-tools` — не включать
   сторонние средства разработки и их зависимости в комплект публикации.
6. Git HTTPS оказался недоступен из-за ошибки schannel SEC_E_NO_CREDENTIALS;
   выбран read-only download официальных архивов GitHub с фиксированными коммитами.
7. Создана локальная ветка `codex/first-release` и исходный коммит без remote —
   сохранить обратимую точку до рефакторинга. Отдельный ZIP исходной точки лежит в build/ub-review.
8. Повторены базовые C++-тесты: 53/53 и 104/104. Добавлены поведенческие тесты
   комплекта; до исправлений воспроизведены три ожидаемых отказа: утечка служебных
   файлов, обход игнорируемых деревьев и неверное имя ZIP в README.
9. Lizard измерил сложность C++: максимумы 65/62/41 для распознавания, сканирования
   и сворачивания. Это CC, не CRAP: процент покрытия C++ этим измерением не получен.
10. Crapper и Dryer упёрлись в один общий кэш tree-sitter в профиле пользователя.
    Общая неверная предпосылка: средства анализа должны писать в AppData.
    Решение — назначить им локальный каталог кэша в build, а не расширять права.

11. По трём воспроизведённым отказам исправлены имена архивов и выбор публичных
    файлов; служебные деревья теперь отсекаются до обхода. Устранена повторная
    работа вместо добавления слоя кеширования.
12. Сохранена исходная точка и выполнен рефакторинг C++: именованные операции
    распознавателя, сканера, сворачивания, конфигурации, уведомлений и палитры.
    После каждой группы изменений повторялись существующие поведенческие тесты.
13. Добавлены проверки упаковки с настоящими ZIP и временными файлами;
    мутируется только частная копия, производственные исходники не изменяются.
14. Mutator выявил платформенные предпосылки: символические ссылки требуют
    прав Windows, а обработчик таймаута использует отсутствующий os.killpg.
    В qa/run-quality.py адаптированы только ввод/вывод изоляции и завершение
    собственного тестового процесса. Неизменённые тесты в каждой копии должны
    пройти до запуска мутаций; правила мутаций официального инструмента сохранены.
15. После первого прогона мутаций усилены проверки метаданных, повторного
    запуска, состава архивов и отказа предварительной проверки. Тестовые отчёты
    сделаны независимыми от текущего red/green-состояния нативного прогона.
    Убрана избыточная передача стандартного значения followlinks=False в os.walk.
16. По новой просьбе пользователя добавлены автор и GitHub в About. Сначала
    реальный диалог дал четыре ожидаемых отказа (имя/ссылка × две палитры),
    затем исправленная DLL прошла все 381 проверки.
17. Обновлены README на двух языках, CHANGELOG и описание проверки. Устаревшее
    сообщение о неудавшейся старой установке заменено результатами свежего
    изолированного теста установщика; отчёт связан с SHA-256 DLL и скрипта.
18. После успешных нативных тестов обновлена фиксация 31 файла по байтам,
    заново проверены PE-ресурсы и собраны окончательные бинарные ZIP.
19. Каталоговый ZIP проверен на чистом portable-профиле; официальный валидатор
    проверил локальные байты, схему, версию и уникальность. Публичный download
    и полный цикл Plugins Admin не объявляются пройденными.
20. Подготовлен отдельный комплект publication-1.0.0: чистая копия repository и release-assets;
    build, dist, .git, кеши, метрики и рабочие копии Notepad++ в исходники не входят.
    Исходные рабочие материалы сохраняются отдельно, во внешний Git ничего не отправляется.

21. Реальный Git checkout обнаружил перевод строк в новых файлах средств
    качества. Исправлены LF у launcher/requirements, добавлен контроль этих
    автоматизаций; сырые результаты инструментов сохраняются правилом -text,
    как остальные нативные снимки. Повторная проверка прошла: 124 публичных файла совпадают побайтно при обоих core.autocrlf, исходные ZIP одинаковы; намеренный CRLF-дрейф отклоняется.

22. Проверен список Git worktree: только текущая рабочая папка, удалять нечего.
    Завершённые mutation workers убираются инструментом; после аварийного
    прогона удалена доступная часть его частной копии. Windows отказала в доступе
    к оставшемуся .pytest_cache внутри игнорируемого target; он не включается
    в исходный архив и не затрагивает исходники. Базовый коммит/ZIP сохранены.
23. Итоговые изменения сохраняются локальным коммитом с причиной и результатами;
    remote отсутствует, push и публикация не выполняются. Комплект сверяется
    с SHA-256 каждого файла и проверяется отдельно от рабочей папки.

## Словарь

- **Fore** — целевой язык Prognoz/Foresight Platform, не компилятор.
- **UDL** — прежние определения пользовательского языка; в этот репозиторий не входят.
- **Базовый XML** — настройки внешнего лексера, которые читает Notepad++.
- **Палитра** — стандартные цвета Light или Dark; пользовательские отличающиеся цвета сохраняются.
- **Автораспознавание** — эвристика для обычного текста в TXT/файлах без расширения/новых вкладках.
- **Комплект публикации** — отдельная чистая копия исходников и окончательные ZIP с SHA-256.

## Результаты

| Область | Измерение и результат |
|---|---|
| C++ src/*.cpp, 135 функций | Lizard 1.24.3: максимальная CC 65 → 9 |
| tools/package.py, tools/release_files.py | Crapper: 7 функций, покрытие функций 100%, максимальный CRAP 8 |
| tools/*.py | Dryer при пороге 0,8: кандидатов дублирования не обнаружено |
| Два модуля упаковки | Mutator: 70 мутаций, 69 обнаружены, 1 эквивалентна, 0 непокрытых |
| Поведение | 53/53 ядро, 104/104 распознаватель, 381/381 интеграция, 17/17 автораспознавание, 40 проверок тем, 16 Python-тестов |

Единственная выжившая мутация меняет секунды фиксированной даты ZIP с 0 на 1.
DOS timestamp внутри ZIP хранит секунды с шагом 2: отдельное сравнение подтвердило
полное совпадение байтов двух архивов. Добавлять тест внутреннего аргумента только
ради уничтожения этого эквивалентного мутанта не стали. Mutator возвращает exit 3;
это **не** отчёт о 100% уничтоженных мутаций. Сырые результаты сохранены.

Crapper/Dryer/Mutator не поддерживают C++ и PowerShell. Поэтому CC для C++ не
выдаётся за CRAP или процент покрытия. CRAP относится только к двум указанным
Python-модулям, а не ко всем интеграционным CLI проекта. Это ограниченный аудит,
не утверждение, что каждая функция всего репозитория удовлетворяет всем метрикам.

Машиночитаемый отчёт и хеши исходников:
[qa/ub-mode-validation.json](../qa/ub-mode-validation.json).
Исходные метрики: [qa/quality-results](../qa/quality-results).
Официальные средства: [Crapper](https://github.com/unclebob/crapper),
[Dryer](https://github.com/unclebob/dryer), [Mutator](https://github.com/unclebob/mutator).
Коммиты зафиксированы в отчёте и requirements-quality.txt.

## Повторение Python-проверок

Дополнительные средства качества не нужны пользователю плагина. В отдельном
виртуальном окружении из корня проекта:

```powershell
python -m pip install -r requirements-quality.txt
python -m coverage run --source=tools -m pytest -q tests/test_release_files.py tests/test_release_archive.py
python -m coverage lcov -o target/coverage/python/lcov.info
python qa/run-quality.py crapper --use-existing-coverage --threshold 9.99 tools/release_files.py tools/package.py
python qa/run-quality.py dryer --threshold 0.8 tools
python qa/run-quality.py mutator --no-coverage --max-workers 2 --test-command 'python -m pytest -q tests/test_release_files.py tests/test_release_archive.py' tools/release_files.py tools/package.py
```

Для мутаций лучше указать абсолютный путь к Python выбранного окружения в
--test-command. Windows-адаптер создаёт частные копии файлов вместо symlink;
неизменённые копии проверяются до мутаций. Кеш парсера расположен в build,
результаты — в игнорируемых .metrics и target. В основной пользовательский
Notepad++ эта проверка не устанавливает DLL.

### Результаты инструментов выпуска 1.1.0

Окончательные тесты упаковки прошли **22/22**. Crapper измерил **11 функций**, **100% покрытия функций** и **максимальный CRAP 7** в `tools/package.py` и `tools/release_files.py`. Dryer не нашёл кандидатов при пороге 0,8 в `tools/*.py`. Полный Mutator-прогон выбрал **86 точек: 85 обнаружены тестами, одна эквивалентная мутация выжила, непокрытых нет**. Выжившая мутация снова меняет секунды ZIP 0 → 1; независимое сравнение подтвердило одинаковые байты архивов. Код завершения инструмента при выжившей мутации сохранён и не выдаётся за отсутствие выживших.

Первый mutation-прогон столкнулся с ошибками декодирования вывода дочерних процессов Windows. Launcher теперь задаёт `PYTHONUTF8=1`; все точки повторно проверены с UTF-8-интерпретаторами и стандартным таймаутом в десять базовых длительностей. Окончательный отчёт — [qa/ub-mode-1.1.0.json](../qa/ub-mode-1.1.0.json), с хешами исходников и [сырыми метриками](../qa/quality-results/v1.1.0). Область этих результатов ограничена указанными Python-модулями; неизменённые алгоритмы лексера покрываются отдельными нативными проверками редактора.

Windows также удерживала каталог завершённого worker при очистке. Адаптер проверяет, что очистка остаётся внутри частного рабочего каталога мутаций, и сохраняет заблокированную игнорируемую копию вместо потери результатов теста. Дополнительные Git worktree не создавались; оставленные диагностические копии исключены из публикации.

Исходный обработчик таймаута предполагает наличие POSIX SIGKILL. Windows-адаптер передаёт этот маркер и проверяет завершение собственного дерева процессов. Настоящий тест спящего дочернего процесса прошёл в обычном пользовательском окружении; ограниченный профиль автоматизации запрещал необходимое управление процессами. Этот необязательный аудит качества следует запускать в обычной сессии PowerShell.
